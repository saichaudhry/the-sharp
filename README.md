| vs. Gridiron Board | Gridiron Board only displays markets. This adds accounts, a bankroll ledger in Postgres, settlement, characters with memory, and a different stack (React + Vercel + Supabase instead of static pages + Flask). |
| Notable features | Server-side prices (no faked odds); bankroll math inside Postgres functions (no double-spend); one shared safety-rules block for all four characters; Kalshi-to-ESPN name matching; entry price vs. live price on open picks. |
| Secrets | `.env.local` locally (gitignored), encrypted Vercel env vars in production. The browser only calls `/api`; Supabase tables are locked from the public key. |

**Run locally**
```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY
npm run dev                  # http://localhost:5180 (app + /api)
```
Run `schema.sql` once in the Supabase SQL Editor.

**Deploy:** import the repo on vercel.com, add the same three env vars. Every push redeploys.

**Stack**
```
React (Vite) ──▶ /api/* (Vercel functions)
                  ├── Supabase Postgres  (players, picks, messages)
                  ├── Kalshi API         (prices, results; no key)
                  ├── ESPN API           (stats; public, undocumented)
                  └── Claude API         (the four characters)
```

**Key files:** `api/_lib/odds.js` (Kalshi + matching), `api/_lib/espn.js` (stats), `api/_lib/persona.js` (characters), `api/_lib/claude.js` (Claude call), `api/settle.js` (payouts), `src/App.jsx` (layout), `src/pages/` (hubs, My Picks).
